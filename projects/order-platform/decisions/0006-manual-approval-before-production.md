## 맥락

배포를 전부 수동으로 하다 보니 한 번에 여러 변경을 모아서 내보내게 됐고,
문제가 났을 때 무엇이 원인인지 가려내기 어려웠습니다.

반대로 전 구간을 자동화하자는 안도 있었지만, 결제와 재고를 건드리는 서비스라
아무도 보지 않은 채 프로덕션에 나가는 것은 지금 팀이 받아들이기 어려웠습니다.

## 결정

파이프라인은 자동으로 두되, 프로덕션 배포 **직전 한 곳에만** 사람의 승인을 둡니다.

- 빌드·테스트·이미지 생성·스테이징 배포·통합 테스트는 승인 없이 진행합니다.
- 승인은 "이 변경을 지금 내보낼 것인가"만 판단합니다. 코드 리뷰를 다시 하는 자리가
  아닙니다.
- 승인 이후는 다시 자동입니다. 롤링 배포와 헬스체크에 사람이 개입하지 않습니다.

## 결과

**얻는 것** — 변경 하나씩 내보낼 수 있게 되어 문제의 원인을 좁히기 쉬워졌습니다.
위험한 순간에만 사람이 개입합니다.

**치르는 대가** — 승인이 리드타임의 병목이 됩니다. `주문 기능 값 흐름` 에서 보듯
대기 시간이 리드타임의 대부분을 차지하고, 승인 대기도 그중 하나입니다.
승인자가 자리에 없으면 배포가 멈춥니다.

승인을 없애는 것은 배포 실패율이 충분히 낮다는 근거가 쌓인 뒤에 다시 논의합니다.
