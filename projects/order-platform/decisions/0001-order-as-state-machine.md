## 맥락

주문은 접수·결제·준비·배송·취소를 오갑니다. 초기 구현에서는 `status` 문자열 필드를 두고
필요한 곳마다 `if (order.status == "paid")` 로 분기했습니다.

분기가 열 곳을 넘어가자 두 가지가 드러났습니다. 어떤 상태에서 어떤 상태로 갈 수 있는지가
코드 어디에도 적혀 있지 않았고, 배송이 시작된 주문이 다시 결제 대기로 돌아가는 버그를
리뷰에서 아무도 잡아내지 못했습니다.

## 결정

주문의 상태와 전이를 명시적인 상태 기계로 다룹니다.

- 허용된 전이만 한곳에 선언하고, 전이는 그 표를 거쳐서만 일어납니다.
- 각 전이에는 그것을 일으키는 **사건**의 이름을 붙입니다. `결제 승인`, `출고`, `고객 취소`.
- 허용되지 않은 전이는 예외로 막습니다. 조용히 무시하지 않습니다.

## 결과

**얻는 것** — 가능한 상태와 전이가 그림 한 장으로 설명됩니다. 새 상태를 추가할 때
빠뜨린 전이가 컴파일 또는 테스트에서 드러납니다. 잘못된 전이가 데이터에 남지 않습니다.

**치르는 대가** — 상태를 바꾸는 코드가 한 단계 우회합니다. 상태 하나를 추가하려면
전이 표와 그것을 쓰는 곳을 함께 고쳐야 하므로, 필드 하나 바꾸던 때보다 손이 더 갑니다.

`주문 상태 전이` 다이어그램이 이 결정의 표를 그대로 그린 것입니다. 표와 그림이 어긋나면
그림이 아니라 표가 옳습니다.
