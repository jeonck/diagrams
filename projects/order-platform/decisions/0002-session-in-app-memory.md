## 맥락

로그인 세션을 어디에 둘지 정해야 했습니다. 초기에는 앱 서버가 한 대뿐이었고,
외부 저장소를 하나 더 운영할 이유가 없어 보였습니다.

## 결정

세션을 앱 서버 프로세스 메모리에 둡니다.

## 결과

**얻는 것** — 운영할 것이 하나 줄고, 세션 조회에 네트워크 왕복이 없습니다.

**치르는 대가** — 앱 서버를 재시작하면 로그인이 모두 풀립니다. 서버를 늘리려면
로드 밸런서에 고정 세션(sticky session)이 필요합니다.

## 왜 대체되었는가

앱 서버를 세 대로 늘리면서 이 결정이 무너졌습니다. 자세한 것은
[0005 세션을 Redis로 옮긴다](0005-session-in-redis.md)를 보십시오.
